| Research Question | Scientific question | Can a research agent improve a frozen multimodal model's calibrated probability that another agent completed a task, using observable evidence and a concise free-text diagnosis under a fixed inference budget? The main JEV model is frozen; only judge prompts, permitted review/recheck use and a small external calibrator change. The judge cannot act on or repair the task. This differs from the earlier jev-agent proposal, which optimizes an acting agent's prompts to execute tasks; here the objective is probability quality on independently verified outcomes. |
| Research Question | Why this is scientific research rather than pure engineering optimization | The variables are requirement decomposition in the prompt, S1/S2 review use and probability calibration. The hypothesis is that examining evidence improves recognition of missing requirements and misleading success claims across modalities. AutoTrust's author-reported AgentRewardBench result motivates this starting point, but ranking AUROC does not establish calibrated Brier loss on new code, SQL and document workflows. The public corpus supports a controlled comparison across split-disjoint scenarios with executable gold; publication of all answers precludes a strong claim of secret-test generalization. |

| Evaluation | Fixed evaluation protocol | Six families: browser transaction state, saved settings, Python repair, SQL analysis, document extraction/calculation and inventory/receipt workflows. Each has 80/24/40 train/dev/evaluation cases: 480/144/240. Every balanced construction batch contains eight independent worlds: four successes and four failures, one each for omission, wrong value, uncommitted change and misleading completion claim. Failure subtype counts per family/split are 10/3/5; outcomes are balanced. All 864 semantic worlds are distinct and split-disjoint; each grouping record contains one case. Wrong values use legitimate domains and former marker values also occur in correct settings. Claims are sampled independently of outcome. Labels are recomputed by verifiers, not copied from mutation tags; the synthetic distribution is not a claim about natural agent failures. |
| Evaluation | Evaluation mode and input | Each ordinary observation has up to 3,000 text tokens, two 768×768 images, 24 transcript records and one final artifact. The current corpus uses 432 rendered UI images; tokenizer/processor enforcement of the planned 8,192-token total context remains pending. The inference interface omits gold state by protocol. A separate scorer reads public gold and executes browser/settings predicates, bounded Python tests, SQL on three databases, exact document arithmetic and inventory/receipt postconditions. Outcomes must be decidable from the visible requirements and observations; the actor's completion claim is not authoritative. No multiple-choice answers are presented: outputs are probabilities, evidence references and free diagnoses. |
| Evaluation | Reward or score definition | Let y be the executable gold completion label and p the predicted probability. For valid JSON, item loss L=(p−y)^2. A malformed verdict, nonfinite/out-of-range probability, invalid evidence reference, or a completed call returning an empty verdict receives L=1. With 240 cases, B=mean(L); score=100×max(0,1−B/0.25). Because every family is balanced, B=0.25 is the constant-0.5 baseline, scoring zero. Preserve the unrounded result. Full marks are exactly 100 iff every verdict is valid and every p equals its true 0/1 label, with complete evaluation and valid resource/scope records. Diagnosis persuasiveness earns no points; this is a probability-quality task. Process crash, invalid policy artifact, global timeout or incomplete dataset execution is unscored, not fabricated zero performance. |

Example: a settings task requests saving a particular timezone. Its observable final screenshot still shows a different valid timezone and the actor claims success. A verdict can be `{"p_complete":0.12,"evidence":[{"kind":"image","image":0,"box":[0.2,0.3,0.4,0.1]}],"diagnosis":"The saved timezone differs from the requested value."}`; the runner attaches the opaque input `id`. The persisted gold state and label are publicly available for audits, but are not part of the ordinary model request.
