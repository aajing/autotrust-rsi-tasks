| Research Question | Scientific question | Can an agent discover a data-dependent quantization recipe that halves the functional distortion of a simple four-bit baseline while preserving a decision model's broader generative and visual abilities? The starting model is a decision model, but the evaluation includes free numeric answers, executable Python and SQL, structured tool calls and image-grounded numeric/spatial outputs. Only one sixth of scored examples directly tests calibrated decisions. The research object is the relationship between calibration data, expert sensitivity, limited precision and transfer across task families. |
| Research Question | Why this is scientific research rather than pure engineering optimization | The hypothesis is that uniformly quantizing every expert ignores unequal sensitivity across layers, experts and modalities. The agent must use public development evidence to choose calibration samples, clipping and bounded precision allocation, then compare on a disjoint but publicly inspectable split of the same six families. A fixed loader removes custom-kernel competition. Ablations should distinguish calibration selection from mixed-precision allocation. The main reward measures distribution preservation under a strict storage constraint; task correctness and latency are independent gates. Success cannot be inferred from one public language-model benchmark. |
| Research Question | Starting environment and artifacts | The package contains deterministic generators, all public splits with gold/PNGs, CPU oracles, tensor selection, accounting and B0/BQ configurations. `taskkit/tensors.py` implements symmetric INT4/INT8 pack/dequant and BF16 conversion on CPU. B0 is the original model; BQ uses INT4/group128/ties-even/max-absolute scaling. The fixed execution path is task-owned CPU reconstruction using the supplied dequantization arithmetic, followed by ordinary pinned-backbone BF16 inference. BQ and all candidates use it. Real weights, ordinary model-loader integration and measured references remain absent. No native four-bit execution, lower resident GPU memory or speedup is claimed; future packed kernels require a different protocol revision. |
| Research Question | Agent's final deliverable | One `solution/quantized-model/` containing packed tensors and numeric scales in safetensors, a declarative `quantization.json`, and a manifest mapping every source tensor to its source hash, bit width, grouping and output tensor. Judge validates only the declared model artifact, deterministically reconstructs BF16 tensors on CPU using trusted arithmetic, then loads the fixed ordinary BF16 runtime. It neither imports the candidate's exporter nor executes candidate Python during inference. Invalid tensor shapes, unsupported fields or external references invalidate the artifact before evaluation. |

| Reference Baseline | Baseline evaluation path | Operator setup runs B0/BQ sequentially and freezes outputs, scores and latency before research. Each probe stores one B0 float32 vector over 262,144 tokens; eighty vectors require 80 MiB, plus scalar BQ distortion. Development uses separate probes. Publish vectors, positions, outputs and hashes. Only Solution copies a previously measured baseline using `solution/materialize_baseline.py`; it performs no inference, quantization, calibration or training. Judge evaluates only the candidate against frozen references. |

| Evaluation | Fixed evaluation protocol | Six families: rational/integer arithmetic; restricted single-return Python checked on twelve inputs; SELECT SQL checked on three databases; exact tool JSON; 448×448 PNG chart/grid numeric/coordinate outputs; binary confidence. Counts: 1,152 practice, 288 development and 576 evaluation, equally divided by family and short/compositional difficulty. All 2,016 gold outputs pass CPU oracles. Canonical concrete groups precede splitting/rendering; IDs are opaque and order shuffled. All inputs, seeds, gold, tests and images are public. Fixed practice/development roots and the persisted evaluation seed reproduce this benchmark; disjoint groups do not imply answers are unknown to participants. |
| Evaluation | Evaluation mode and input | Five families use native System 2 free generation with the System 1 adapter disabled, not answer-letter logits. Trusted prompts/templates specify greedy decoding, thinking disabled and at most 160 output tokens. Inputs are capped at 2,048 text tokens and one 448×448 image; generated gold answers fit the output budget. Invalid/truncated answers are incorrect. Each record has an exact oracle or executable checker. Only confidence records enable the unchanged System 1 interface and use binary labels. Probe probabilities use frozen oracle prefixes independently of generated answers. Judge runs one fixed model at a time. |
| Evaluation | Reward or score definition | Let A be macro correctness across six families; confidence correctness thresholds its probability at 0.5. Let B be mean binary Brier loss on confidence records. Let D be mean total-variation distance from B0 over eighty probes, and DQ the BQ value. Eligible completed runs require A≥A0−0.01, every family accuracy≥its B0 value−0.03, B≤B0+0.01, model bytes≤0.40 times B0 bytes, peak GPU allocation≤64 GiB, and timing latency≤1.10 times BQ. Artifact bytes count every delivered weight/scale/adapter and frozen/shared dependency once; documentation is excluded. Deterministically reconstructed BF16 runtime tensors are ephemeral derivatives, not extra submitted weights; no independently fitted runtime values are allowed. These derivatives are excluded from delivered-storage bytes, but their reconstruction time and actual memory remain charged. Compressed expert source originals cannot be additional inference dependencies. Score is `100 × clip((DQ−D)/(0.50×DQ), 0, 1)`. Full score requires D≤0.50×DQ and every gate. Packaging requires DQ≥0.000001. Complete gate failures score zero; crashes, invalid artifacts, timeout and incomplete runs are unscored. |
