# jev-visual-control-rsi protocol v2 (public evaluation)

Local prepared task; not submitted to official review. Candidate output is continuous action JSON. Native JEV decision questions are an internal perception interface, not the evaluation target.

## Episode contract

`Controller(model)` implements `reset()`, `step(observation) -> action`, and `memory() -> JSON`. Each episode launches a fresh worker process. An action contains exactly `dx`, `dy`, `dz`, `grip`: finite non-Boolean numbers, displacements in metres in [-0.04, 0.04], aperture in [0,1]. The owner interpolates movement over 0.5 simulated seconds in 0.002-second ticks, then changes aperture. There are 120 actions, at most 240 model calls, and a 90-second simulated-time upper bound; 120 half-second actions actually exhaust the step cap at 60 seconds.

The observation contains goal text, placement descriptions, delayed 384×384 top/oblique PNG images, image age, **current own** gripper pose/aperture, previous action, remaining steps and public orthographic calibration. Own proprioception is current; images are one step old in hard and two in harder, limited by elapsed steps at reset. Crop/composition must derive from these images and preserve their delay. No target coordinates, body handles, attachment identity, scene seed, masks, depth or feasibility trajectories enter IPC.

Call `model.decide` with exactly `kind`, `state`, `question`, `options`, `thinking`. State is a bounded list of text and `{"image":"data:image/png;base64,..."}` parts. `thinking` must be `off`. Native `choice` accepts 2–16 option strings; `noul` and `score` use `options:null` and return the release's two or six calibrated probabilities. Each action step requires one or two requests, each with 1–4 images no larger than 384×384 and at most 4,096 processor input tokens. The server launch script sets a 4,096-token context cap; the broker also rejects incompatible usage accounting. Expanded-choice strategies and System 2 are excluded. A rejected or missing real model response makes the attempt unscored; there is no fallback answer. Endpoint provenance and precise token compatibility still require the pending H100 integration check.

Candidate-owned prompt text, crops, resize/contrast/composition, probabilities, motion logic and 64-KiB declared episodic memory may change. Learned semantic perception must use JEV. Independent object detectors, semantic color locators, target-pose reads, published per-scene image/seed lookup tables, auxiliary models, changed model weights and imported oracle planners are prohibited. The worker serializes declared memory, but this is not proof that arbitrary Python has no undeclared memory. Process restart prevents ordinary cross-episode state retention; process/file audits and the Harness threat model remain relevant.

## Fixed environment and full marks

The **authoritative implemented lane is a Pillow-rendered CPU kinematic surrogate**, inspired by the upstream robot-arm demo. It is not MuJoCo rigid-body execution, and does not claim real-robot transfer. A held object has fixed 45-mm gripper offset; proximity attachment requires ≤12-mm horizontal/vertical error. Released objects fall vertically under 9.81 m/s² and settle on the table or tray. Cylinders use conservative bounding boxes for carried-object safety. There is no angular control, compliant contact or lateral pushing. Empty-gripper contacts with loose objects are not a rigid-body interaction model.

The owner checks each interpolated tick for workspace/barrier collisions, carried-object/table/object intersections, and non-target displacement >15 mm. At worst, samples are 0.277 mm apart, below the smallest frozen safety geometry; this is sampled swept checking, not an exact continuous collision theorem. Both apertures and Cartesian deltas may be continuous. Closing ≤0.2 attaches at the endpoint; opening ≥0.8 releases.

Four families appear in every split: visually similar distractor pick/place, narrow precision placement, transport around a barrier taller than the allowed gripper height, and ordered placement of two objects into separate trays. Hard has four objects/one-step image delay; harder has six/two-step delay. Brightness, floor grid, source/tray positions and the single-camera partial occluder vary. The second camera remains free of the overlay. F2 center tolerance is 6 mm / 3 mm. F4 first placement must have settled for 0.5 seconds before grasping the second target. Every requested object must be fully inside its tray, released and stable for the final 0.5 seconds. Holding an object above a tray does not succeed.

There are 16 train, 6 development and 6 evaluation scenes per family/tier cell: **128/48/48**. Seed HMAC namespaces and canonical-geometry hash partitions are disjoint. Canonical hashes omit the seed and appearance-only variation. All 224 frozen records have public full-state collision-free reference replay certificates. These prove the stated surrogate goals are reachable, not that JEV can perceive or complete them.

Judge score is `100 × successful episodes / 48`, equivalent to equal weighting of the eight cells. **100 requires all 48 successes.** Ordinary missed grasps, wrong placements, collisions, order failures, precision misses and step exhaustion contribute zero and the suite continues. Invalid schemas, illegal actions, scope/cost violations, infrastructure failures, crashes, global timeout or incomplete coverage invalidate the attempt: no numerical reward is published. The score is computed from newly executed owner events, never candidate success declarations.

## Ownership and budget

All task archives, scene records, seeds, generator/evaluator code and full-state reference trajectories are **public research material**. Researchers may read and reproduce them; no answer is concealed and no encryption or access grant is required. `scripts/export_research.py` copies the published asset inventory for inspection. `scripts/materialize_baseline.py` separately builds the execution artifact. Candidate methods may use general knowledge of the rules and distributions, but may not extract published per-scene poses, cache their solutions or recognize a scene to replay its reference. Data access is allowed during research; the restriction is how the submitted controller obtains episode actions.

Default execution uses native observation/model JSONL IPC in one container, compatible with the existing Harness model. It needs no user namespace, Bubblewrap or extra container privileges. An optional separate-UID launch uses ordinary file permissions if the host supports it; this defense is not required for the default lane. Task-owned entrypoints validate live actions/counters and the frozen worker transport. Researchers must stage only reviewed controller code/configuration in the execution directory. Neither the subprocess nor static artifact review proves the absence of encoded public answers under arbitrary root access. Report public-set fitting and memorization risk, and do not claim previously unseen evaluation or absolute isolation. The optional UID lane and actual Harness deployment remain unexecuted here.

Work: two hours, 20,000 model calls, 160 newly sampled exploratory episodes. `--work-id` selects an operator-owned persistent ledger across local Work invocations; keep the same ID for a candidate. Judge: 90 minutes, 48 episodes, 11,520 calls. The persistent Judge ledger charges at most 12 attempted scored calls, including controls, failed admissions, crashes and timeouts. Overall 24-hour trajectory timing, optional recorded extension to 48 hours, and owner-controlled candidate-ID creation are orchestration responsibilities; the local scripts do not replace Harness scheduling. Budgets include startup. Reserve 15 minutes per cycle for handling; throughput and memory remain unmeasured.
